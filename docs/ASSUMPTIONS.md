3. **Merkle hashing:** Phase 1 refuted the report's "RFC 9162 hashing" phrasing — C2SP checkpoints hash over the **RFC 6962** tree. The log implements RFC 6962 leaf/node hashing (SHA-256, 0x00/0x01 domain separation), C2SP-style signed checkpoint text, Ed25519 signatures (JDK built-in). RFC 9162 is cited as the CT v2 framing (Experimental), not as the hash spec.
4. **JSON:** JDK-only dependencies means no Jackson/Gson. Evidence JSON is produced/parsed by a small hand-rolled writer/parser in the `evidence` module (flat record schema, strict escaping). Deliberate scope cut; schema is versioned (`schemaVersion`) so a real parser can replace it later.
5. **Validation field semantics:** Per NIST Rev.2, *validation* is a decision. The EvidenceRecord therefore stores `verification` (machine results: method completed, canary/control outcomes) and `validation` (decision: ACCEPTED / REJECTED / PENDING, decider, rationale) as separate objects. The library can *propose* a validation decision from verification results; only a caller acting as validator can set ACCEPTED. The CLI defaults to PENDING unless `--accept-validation` is passed, in which case the operator is recorded as decider. (Simplest defensible reading of Rev.2.)
6. **Rollback logging order:** On failed pre-commit validation, the ABORTED event is appended to the log (and witnessed if a witness is configured) **before** the vault restore executes — restoring first would let rollback hide failures (Phase 1, N-3 rewording).
7. **Grace window:** Report's optional GRACE is **cut** from v1 (AWS KMS prior art; adds a second key-lifetime state machine). Listed as future work in PLAN.md. Scope rule from the task: cut features before cutting verification quality.
8. **Witness model:** "Independent witness" = a separate Ed25519 keypair held in a separate file/process invocation (`jvd witness-cosign`), co-signing checkpoints C2SP-cosignature-style. True organisational independence is an operational property; the code enforces *key* independence (refuses to cosign if witness key == log key) and the docs say so.
9. **Backdating detection:** An offline verifier cannot detect backdating from a single log alone. Detection implemented is the strongest honest version: (a) record timestamps must be monotonic non-decreasing along the log; (b) a record whose timestamp predates its checkpoint's witnessed time, or a checkpoint cosigned by the witness, binds time from the witness side; (c) fork detection requires comparing two checkpoints (operator-provided second checkpoint file). Docs state this limit explicitly rather than claiming magic.

## Addenda from the build/experiments (Assumptions 15–17, logged when discovered)
15. **Maven network (build subagent):** Java processes have no direct TCP in this sandbox (denied by the runtime permission layer); Maven Central is reachable via curl/python through the egress proxy. `scripts/prefetch_maven_deps.py` downloads the dependency closure via curl into the local `.m2`; `mvn` then resolves locally. On a normal network this step is unnecessary.
16. **Consistency-proof encoding (build deviation):** jvd's consistency proofs use range-tagged frontier nodes with the same RFC 6962 hashing/roots; the proof *encoding* is internal to jvd-verify (verified exhaustively for all (m,n), n≤32). It is not byte-compatible with an RFC 6962 SUBPROOF wire format — stated here so nobody claims otherwise.
17. **Known issue — ProcScanner vs ZGC: FIXED 2026-11-10 (follow-up commit after 158a268, user-approved).** The shipped `verify` module skipped file-backed mappings, but ZGC maps its heap via `/memfd:java_heap`, so on a ZGC target the scanner saw no heap. Its positive control then failed too, so the run reported **INVALID, never a false NOT_FOUND** — safe, but ZGC memory verification was effectively NOT_CHECKABLE. Fix: `ProcScanner` now also scans `/memfd:` regions (library mappings stay skipped), mirroring the experiment scanner. Regression test `CanaryVerifierTest#nowipeTargetIsFoundUnderZgc` was added *before* the fix and failed exactly as predicted (all counts 0, controls INVALID); after the fix it passes, and the full build is green at 35 tests (34 prior + this one).
